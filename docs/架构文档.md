# 恋爱吧管理中心 · 架构文档

定位：和我恋爱吧的管理项目，直连同一套 PostgreSQL/Redis，读写分离管理一切数据（读走分页参数化查询加PII视图掩码，写走事务加审计留痕），未来一块部署到服务器。

## 环境同源（一块部署）

- 与和我恋爱吧共用同一 PostgreSQL/Redis/Network（`lovewithme-network` 外部引用），不自建双栈双库。
- 数据库单源：`和我恋爱吧/database/000_baseline.sql`＋`backend/database/migrations/`（只读参照，禁止复制粘贴；思考记录落库见 018 迁移）。
- 主配置源：`和我恋爱吧/.env`；`infra/envs/.env.*` 仅覆写管理端口与管理侧凭据，
  同名键（`DATABASE_URL`/`REDIS_URL`/`JWT_SECRET`/`ADMIN_PHONES`/`ALLOWED_ORIGINS`）留空运行时补齐。

## 服务拓扑（前后分离）

| 服务 | 部署位置 | 端口 | 技术 | 职责 |
| --- | --- | --- | --- | --- |
| management-backend | 服务器 | 3100 | 与和我恋爱吧同栈 | 账号/聊天/思考记录/封禁/审计/统计读写 API，直连同库 |
| management-frontend | 用户本地 | 5175 | Vue | 登录/账号/聊天/思考链/封禁/审计/统计（唯一可对接后端的专属前端，省服务器资源） |
| tts-service | 随后端一块部署 | 8001 | FastAPI / edge-tts | 语音合成（Edge 主路＋离线兜底） |
| n8n | 随后端一块部署 | 5678 | n8n 2.37 | 自定义节点工作流 |

本地启动只起前端＋语音，后端走服务器远端健康检查；部署脚本只部署后端及随行服务。

## 核心链路

1. 管理读写：本地专属前端 → 服务器管理后端 → 共享 PostgreSQL/Redis（参数化查询＋限频；读走分页查询，写走事务＋审计留痕）。
2. 鉴权：管理后端签发管理令牌（管理员账号登录），管理接口走“签发端同源验签＋管理员门禁”；和我恋爱吧签发令牌仍兼容只校验。
2b. 会话生命周期（FP-03）：会话双 Cookie 名/作用路径与 `guan_li_shua_xin`/`guan_li_shua_xin_chi_jiu`/`jwt_blacklist`/`jwt_yong_hu_cheXiao` Redis 前缀的唯一真源在 `管理后端/src/会话.ts`（下发/抹除 Cookie、登记与读持久标记、注销刷新令牌、创建登出路由均出自此）；「记住密码」= 服务端持久标记决定的持久刷新 Cookie，密码零落盘；续期为一次性轮换，前端以单飞复用同一在途 Promise 规避并发第二次必 401；注销按 `jti` 写黑名单吊销当前令牌并清发双 Cookie。
3. 专属绑定：管理后端 CORS 只放行本地前端来源＋服务器同源，非白名单一律拒收；无 Origin 非浏览器直调仅放行健康检查。
4. 语音：和我恋爱吧经 `TTS_SERVICE_URL` 调用随行 tts-service。

## 横切约定

- 写操作一律走事务＋审计日志留痕；备份仅只读转储共享库，恢复被拒绝（到和我恋爱吧侧执行）。
- 用户可见文本走文案模块；配置走环境变量；中文标识符。

### 一、eslint 键位判定（管理前端/eslint.config.mjs）

- 词典已按域拆成 `src/文案/*.ts`：分类名取聚合出口的键，键名取各域文件的成员名，扫描面覆盖整个目录。
- 词典坐标词表只有处在**键位**时才是坐标；写在文本、可见属性、比较运算或赋值右值里就是手打的显示名。
- 键位共四处：①成员访问的属性位（`账号文案['昵称']`）；②对象键位（`'昵称': …`）与显式登记的 `键:` / `文案键:` 值位；③列构造与 `取文案` / `取列` 等助手的键位实参（含 `['分类','键']` 这种成对键位）；④类型标注与模块路径等本就非可见的位。文本插值、比较运算、赋值右值、可见属性一律不是键位。
- 后端数据键全集 = `列定义.ts` 每项登记的首个实参，外加同文件导出的 `响应行键` 表。
- 徽标族名取自 `枚举映射.ts` 的 `徽标族` 联合类型，是单源坐标而非可见文案。
- 样式钩子词表实读自 `src/主题.css`：class 位只允许写 CSS 真声明过的钩子名，写「高危」这类没声明过的中文词即把显示名走私进钩子位。静态属性写死词典坐标词（`slot="详情"`）同样判红。
- 只有白名单属性的值是给人读的文案；`class` / `id` / `data-testid` 之类是钩子名。内部码位的值只用作 CSS 类名、图标名、能力位、路由路径、测试标识，不上屏；模板里的内部码属性位是图标名（`TuBiao` 的 `ming-cheng`）与测试钩子，可见属性与条件/事件表达式都不在此列。
- 模板属性按实名判定：`v-bind:class` 与 `:class` 的实名都是 `class`，`v-if` 是 `if`，`@click` 是 `on`。
- 取数/登记助手的键位实参下标是白名单：只有这些位置的字面量算坐标，其余实参一律按可见文案处理；列取值必须回 `列定义.ts` 导出的列对象，在助手的键位上写字面量即为绕开单源。

### 二、构建体积度量口径（vite.config.ts、src/构建指纹.ts、src/__tests__/体积预算.test.ts）

- gzip 字节数由 vite 的 `体积统计插件` 在 build 期对**内存里的产物字节**做 `gzipSync(level 9)` 得到；不读 dist 文件系统，也不与 vite 控制台的 gzip 混用。事后遍历 dist 会把 `build-stats.json` 与产物目录差异算进去，与控制台口径相差约 3kB，足以造成「测试绿而真实首屏超标」的假达标。

### 三、测试桩注册顺序（src/__tests__/setup.ts）

- RouterLink 桩的注册名必须与 vue-router 的 `app.component('RouterLink', …)` 逐字相同。
- VTU 先安装挂载点全部插件，再执行全局混入。桩以全局混入的 `beforeCreate` 检查目标 app 的组件注册表：真实 RouterLink 已存在时完全不注册；不存在时只注册一次桩。禁止退回无条件全局插件或 `config.global.components`，前者会与真实路由重复注册并产生 Vue warning，后者只对挂载根组件可见，嵌套组件仍解析不到桩。
- FP-05 起显式 `config.global.stubs = { transition: false, 'transition-group': false }`：VTU 默认把 `<Transition>` 桩成透传容器，被包裹元素的根 `classes()`/`attributes()` 因此读空——动效守卫要断言的正是这些类名与 `role`，桩会把"过渡真的挂上了"变成假绿。代价是离场节点不再于同一帧内消失，任何新写的断言若依赖"节点立即移除"必须改用 `find` 的存在性而非帧时序（FP-04 的 out-in 方向探针按渲染期类名标记 + `findAll('section')` 计数断言，其中等待过渡收尾的 60ms 等帧是显式时序依赖，改它会改探针语义）。
- FP-09 起 `src/__tests__/确认层.test.ts` 的 `等离场()` 不再是定长 sleep，而是「轮询到层节点从 document.body 消失、上限 1s」：过渡收尾由 rAF 排帧决定，用例数增加后工作线程互相抢 CPU，写死 50ms 会在满负载时先于离场完成而误判红（新增两个请求层测试文件后即复现）。轮询有上限，所以"层关不掉"这类真缺陷照样判红，不得改回定长等待，也不得改成无上限死等。

### 四、跨端直读字面写法的耦合点

- 后端测试与前端守卫一律用 fs 直读对端源文件做机械解析：`管理后端/src/路由/思考.ts`（列清单）、`管理前端/src/列定义.ts`（登记面与 `响应行键`）、`管理前端/src/App.vue` 的导航数组字面结构、`管理前端/src/stores/登录.ts` 的角色能力白名单、`管理前端/src/术语.ts` 与 `src/术语/*.ts`、`管理前端/src/文案/*.ts`、`管理后端/src/文案.ts::字段显示名`、`管理后端/src/错误码.ts`、`docs/契约.md`、`docs/术语表.md`。解析失败即抛错，禁止静默通过或空跑。
- `管理前端/src/__tests__/列守卫.test.ts` 的 `透传表对前端表`：键是后端真库表名镜像（`管理后端/src/路由/思考.ts` 的 `思考查询` 第二实参），不是前端可见文案，改名即断链。
- `docs/契约.md` 第 8 行的 RBAC 角色行由 `管理后端/src/中间件/管理员.ts::角色能力矩阵` 按能力中文口径逐字派生，改任一侧必须两同改；`docs/契约.md` 十五节码表、`管理后端/src/错误码.ts`、`docs/术语表.md` 六「错误码」行三方逐码同源。
- 守卫里的「反证样张」是故意喂给扫描器的假数据（假键名、伪装成后端原码的旧称、假来源名），删除即让对应用例失去反证：`视图守卫.test.ts` 的夺舍日志伪装样张与旧称不上屏断言、`术语守卫.test.ts` 的假键名清单与假来源名断言。它们命中旧称扫描属预期，逐条以用例标题为凭，不得当作残留清理掉。
- `管理后端/tests/集成/透传列清单.test.ts` 的 SQL 解析判据：表级约束段（`UNIQUE (...)`、`CHECK (...)`）不是列，必须整段跳过；列片段里的函数调用（`gen_random_uuid()`、`VARCHAR(50)`）由「按括号深度拆段」保证不被逗号切坏；迁移按生产执行顺序（`init.sql` 先、迁移按文件名升序）解析，`DROP TABLE` 清空该表此前的列，因为 `CREATE TABLE IF NOT EXISTS` 在表被删后即可重建生效（006 删 记忆/对话摘要、007 以存根重建），所以 init.sql 旧 DDL 的列不得再算作出处。派生列（查询表达式的 `AS` 别名）与「未上屏列」各自逐条登记理由。真实库对账必须由 `TEST_DATABASE_URL` 指向的独立测试库执行，缺失或不可达均直接失败，不得回退共享 `.env` 或静默跳过。

### 五、时间列口径（src/配置.ts、src/列定义.ts）

- 时间显示格式常量 `时间展示格式 = 'YYYY-MM-DD HH:mm:ss'` 只在 `src/配置.ts` 出一份；渲染只在 `src/列定义.ts` 的时间列实现一处；视图与组件不得再自写 `toLocaleString` / `toISOString` / `getFullYear` 一类的第二份格式化。
- 折算规则：带显式时区（`Z` 或 `±hh:mm`，含 `2026-09-21 03:04:05.120Z` 这种空格分隔形）的时刻，按**浏览器本地时区**输出；不带时区的后端墙上钟不位移，只做形态归一；只有日期没有时刻的值原样输出，不伪造 00:00:00；空值走 `通用.未记录`，解析不过的原样输出，一律不编造。
- 表格与行快照共用同一个 `单元格文本` 入口，因此快照里的时间与表格里必然同形。被值域依赖判为「不适用」的列仍先走 `通用.无适用值`，不受时间口径影响。

### 六、表格版式钩子口径（src/主题.css、列定义.ts::单元格类）

- `.字段` 只声明外观（含 `min-width: 150px`）；`flex: 1 1 150px` 只在 `.账簿 > .字段` 声明。150px 是**宽度**基准，只有横向换行的筛选行（`.账簿`）才能拿到它；一旦纵向卡片（`登录页.vue` 的 `.印卡`、`封禁管理.vue` 的 `.封禁卡`）或栅格（`.双栏`）里还留着这条 shorthand，flex-basis 就变成高度基准，把输入框撑成 150px 高。新增卡片容器因此不需要任何新类名，也不再需要补一条覆盖规则。
- `单元格类` 的返回值只能取自 `主题.css` 真声明过的钩子：`编号` / `数字` / `地址` → `数字`，`链接` / `插槽` → `操作`，其余为空。
- 操作列用 `display: flex` + `gap: 8px` + `align-items: center` 统一「详情」链接与行内按钮的间距与基线；`数字` 列用 `white-space: nowrap` + `overflow-wrap: normal` 覆盖 td 级的 `overflow-wrap: anywhere`，避免手机号与 IPv6 在窄列被断成两行。

### 七、管理后端可见文字与错误码口径（管理后端/src/文案.ts、错误码.ts、校验.ts）

- `文案.ts` 是管理后端对外可见文字的唯一真源：只给管理员能照做的结论与下一步，不叙述内部实现；技术原因走服务端脱敏日志，处置知识落在 `docs/契约.md` 十五节。
- `错误码.ts::错误注册表` 是码、HTTP 状态与默认可重试性的唯一真源；`错误码` 由注册表派生，失败响应运行时再次校验注册表与状态一致，路由、中间件不得手打码字符串。
- 失败包络规范字段是 `code/message/traceId/retryable`，可选 `retryAfterMs/fieldErrors`；`ti_shi/cuo_wu_ma` 仅为同值兼容别名。参数错误把机器字段留在 `fieldErrors`，界面消息只出字段显示名。
- `/api/ready` 依赖缺失或探测失败也走注册表失败包络；健康探针不返回依赖名、驱动异常或连接串。
- `日志.ts` 对模块、消息和详情递归脱敏，移除密码、Cookie、令牌、API key、授权值与连接串凭据；SQLSTATE、堆栈、路径和第三方原文只允许进入脱敏日志。
- 角色与能力一律由服务端身份接口回传，前端只做入口隐藏，不作可信输入；身份以服务端查库结果为准，供刷新页面后重建权限视图。

### 八、前端错误展示口径（管理前端/src/api/请求.ts）

- `请求.ts` 是唯一网络错误归一点，继续使用浏览器原生 `fetch` 与 `AbortSignal.timeout`，不引第三方 HTTP 库。传输中断、超时、非 JSON/非包络分别产稳定前端分类码，任何失败都不再是空码“未知错误”。
- 服务端包络只信规范 `code`；白名单外新码保留原码，消息、影响、下一步降级为 `文案/通用` 的安全中文。已知码携带 SQL、堆栈、路径、环境、驱动或第三方原文时拒绝上屏。
- `取错误展示` 是唯一拆分点，返回消息、错误码、影响、下一步、可重试性、追踪编号与可选字段错误；`XiaoXiTiao` 是唯一错误渲染出口，并只在 `retryable=true` 时显示“重试当前操作”。
- 每个页面用请求展示闸门给错误与结果加批次；发起新请求、切换路由或卸载页面后，旧批次不得覆盖新页面，错误态不得伪装空态。
- 401 清会话并跳登录；`buTuiDengLu` 的续期/注销由调用方处置。网络、超时、依赖与限频按注册表/包络的 `retryable` 与 `retryAfterMs` 展示，不按 HTTP 文本猜码。
- 诊断日志只记录来源、HTTP 状态与追踪号，不记录响应原文、URL 查询、密码、Cookie、令牌或 API key。运行时基线仍为 `AbortSignal.timeout` 与 `credentials:'include'`。

### 九、守卫判据（管理前端/src/__tests__ 与 管理后端/tests）

- 词典引用两形同时识别：拆域前的 `取文案('分类','键')` 与拆域后的 `分类文案.键`，识别面只增不减。
- 去插值会把 `{{ '昵称' }}` 整段抹掉，故插值内部单独扫：整段就是中文字面量即裸字面量上屏；条件表达式里的中文字面量（`v-if="x==='超级管理员'"`）同口径。
- 列定义的表头机械扫描：占位类键只允许当占位提示，不得充当表头。组标题渲染点是 `YeMei` 的 `:biao-ti` 与 h2~h4 里以 `取文案` 领起的具名标题；组说明必须渲染在本组组标题之下，一组一说明，不许蹭上一组的标题；互斥输入组的组说明必须真有渲染点。
- 枚举列表头显示名集合是下拉判定依据：标签命中它说明该输入框填的是枚举码，必须改成 select；select 块里的 `v-for` 必须引 `枚举映射` 导出的 `<族>选项`，且该导入来自族文件而不是视图自写。
- 提交协议实读：筛选后最近一次调用的第 N 个实参，取不到即抛错，禁止断言空跑。同一页里图例/序列名不得与卡片标题同值。
- 死键与引用形态（V-05）：只有白名单里的六种写法算真引用，任意子串命中（含注释、无关字符串、自声明、随机下标）一律不算；错误码形态判为全大写且带下划线或至少四长度；已登记拉丁词元是术语显示名里的整段拉丁（IP、UUID），是唯一合法的拉丁出身；裸拉丁占位判定（S-01）：词典值里的拉丁词元既不是已登记术语的整段、也不是错误码形态，即为悬空占位符。
- 显示名内嵌强制原子化（V-08）只覆盖两类词：三个管理角色显示名 + 全部枚举显示名；只用于包住短词的更长已登记词取术语原子、词典键名、枚举显示名、数据键与别名，整句文案值不参与，否则句子会自我豁免；只认「不能被更长已登记词包住」的整词命中。
- 键名扫描覆盖全部分类且按整词匹配，词边界来源全部取自单源（已登记术语的键与显示名 + 全部禁用别名），不额外造词表。
- 首屏锁（FP-09C）：`App.vue` 只引 `管理角色` 一族，且该族沿 `./` 相对链可达的词典域只有 `通用` + `账号枚举`；引用闭包按目录内相对 import 求可达集，即首屏体积的实际来源。术语表三向同步的全域锁覆盖面必须大于 FP-09A 留下的局部锁。
- 表头单源（L-14）：同一显示名在「表头类键」里只允许有一个词典键，判定面精确到表头，不做显示名全局唯一——`思考阶段` 与 `关系阶段` 是两个概念同名「阶段」属正确建模，后者只出值不出列名，因此不进入表头键清单。
- 值域依赖（S-02）：登记面只有 `列定义.ts` 一处，守卫按表逐列反查；`应登记值域依赖` 是术语表 八、17「仅在被封禁时才有值」列清单的守卫侧 oracle，与被测登记面对向核对，任一侧缩水即判红；依赖列已取到「不适用」那个确定态时，值域依赖列不得再出「未记录」。
- 跨表歧义键不猜显示名：`ID` 在 审核列表 是「目标编号」、在 思考记录 是「记录编号」，只保留原形，歧义清单由 `列定义.ts` 导出、`列守卫` 锁死。结构体内部键的显示名只登记与 `管理后端/src/文案.ts::字段显示名` 同值且术语表已登记的键，逐条跨端核对。
- 渲染方式判别只在 `列定义.ts` 出一份，视图不得再自写 `'徽标'` / `'链接'` 这类值域字面量；`响应行键` 是行数据里未被列定义登记的响应键的唯一声明处；`页签快照表` 是思考链中文表名字面量唯一允许出现的地方，页签原码与管理后端的页签标识同值且不上屏。
- 思考事件值域以三处权威出处逐条互证：生产端服务白名单、库层 CHECK 约束、管理端入参白名单；同一列存在两形原码时，契约按反引号分组登记，逐组取码并保留中文形。
- 引用豁免清单在 FP-08 已归零，只允许继续收紧，不允许重新登记；`关系阶段` 生产侧两条写入链对同一列分别写拼音码与中文档名，两形都是库里的真实存量值。
- 全库枚举筛选点的穷尽清单（FP-14 下拉化四处 + 既有下拉四处）由 `视图守卫` 锁定，新增筛选点必须同步该清单，否则判红。
- 动效守卫（FP-08 收紧后）不再有任何"存在性检查冒充封闭判据"：`恒定:权限位` 要求表达式全等 `登录仓库.(可高危|可封禁|可封禁审核)`、能力写点封闭在 `设置身份`/`同步存储`/`退出登录` 三函数体内、且路由源码里确实存在"持久冷启动 → await 冷启动会话 → 重新判定"的放行路径；`恒定:分支` 额外要求表达式禁含 `?`/`||`/`&&`/`.length`；`恒定:装载属性` 必须逐个真读到调用点 `:shuo-ming=` 的实参是文案常量或字面量；`恒定:内建过渡` 已整体废除（"组件根有动画"不等价于"组件挂载/卸载有动画"），条件节点的标签一律不得是 `XiaoXiTiao`/`ShuJuBiaoGe`/`QueRenCeng`。
- 台账的穷尽性有两个独立源：正则模板扫描器与 `vue/compiler-sfc` 的模板 AST，逐文件对拼计数，分叉即红；扫描器还把两条假绿通道堵成判红——`v-for` 与 `v-if` 同节点（Vue 的 `<Transition>` 只接受单子节点）、`<Transition>` 的直接子是 `<template>`（该用 `<TransitionGroup>`）。`挂名族清单` 只认字面 `name="…"`，`:name` 绑定全站只允许 `App.vue` 的方向感知路由过渡一处。
- reduce 通配会连带抹掉 `fill-mode` 的填充值，因此"可见终态不得外包给 animation 填充"是机检不变量：`animation`/`animation-fill-mode` 带 `both`/`forwards` 的规则，同规则体内不得出现非零 `stroke-dashoffset`、非 1 的 `opacity`、非 visible 的 `visibility`、`scale(0)`。`!important` 动效声明与 reduce 枚举禁令的扫描面自 FP-08 起覆盖全站（`主题.css` 与所有组件 `<style>` 块），不再只看 `主题.css`。
- 防第三方 HTTP 库回流的扫描面自 FP-07 起不止 `src/**/*.ts|vue` 的 `from 'axios'`，还包括 `管理前端/package.json` 的 dependencies/devDependencies 键与 `package-lock.json` 全文（大小写不敏感命中 `axios` 即红）：依赖最容易从 lock 一侧被 `npm i` 悄悄带回，只扫源码等于留了第二条来路。由 `冒烟.test.ts` 的「请求层零第三方 HTTP 依赖」一条用例同时锁两层。
- 会话线路键与缓存前缀（双 Cookie 名 ＋ `jwt_blacklist:`/`jwt_yong_hu_cheXiao:`/`guan_li_shua_xin:`/`guan_li_shua_xin_chi_jiu:`）的字面量只允许出现在 `管理后端/src/会话.ts`，读写两侧一律引常量；由 `管理后端/tests/单元/会话.test.ts` 的「FP-07 会话线路键与缓存前缀单源」全量走查 `src/**`，并带一条喂假源的反证，防守卫空跑。
