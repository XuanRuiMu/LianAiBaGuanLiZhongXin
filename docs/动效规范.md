# 恋爱吧管理中心 · 动效规范

管理前端的运动（motion）单一真源。承载「改了就会坏」的动效不变量，实现与守卫分别为 `src/主题.css`（token 与全部动效类）、`src/动效.ts`（方向判定纯函数）、`src/App.vue`（路由与侧栏接线）、`src/__tests__/动效守卫.test.ts`（机器锁）。本文件不重复粘贴判据实现，只给口径与选型理由。

## 一、运动 token 表

节奏值（时长 / 延迟 / 缓动 / 位移幅度）只允许出现在这张表里，消费处一律 `var()` 引用。命名沿既有 token 风格（`--圆小` / `--影` / `--淡墨`：族名 + 档位词）。

| token | 值 | 语义 | 使用者 |
| --- | --- | --- | --- |
| `--时长微` | 120ms | 即时反馈与布局让步档：按压、轨道塌合、离场淡出 | 侧栏栅轨、`.按钮次`/`.标签页 button` 的 transform、页面与侧栏的 leave |
| `--时长短` | 160ms | 表面态档：颜色 / 边框 / 阴影的角色切换 | 输入框、按钮、表行、页签、侧栏链接、主题色翻转 |
| `--时长中` | 240ms | 进出场档：页面入场、行与卡片上浮、进度条填充 | 路由 enter、列表错峰、`.条充`、SVG 点现 |
| `--时长描` | 800ms | 图表描线档（一次性叙事动画，不用于交互反馈） | `.描线` |
| `--时长环` | 1300ms | 循环档（骨架微光，唯一允许 infinite 的时长） | `.加载条::after` |
| `--步进差` | 55ms | 错峰步长，乘 `--位` | 行/卡片/点的 `animation-delay` |
| `--缓出` | cubic-bezier(0.22, 0.61, 0.36, 1) | 入场减速：物体到位即停，不弹 | 全部 enter、上浮入场、描线、点现 |
| `--缓入` | cubic-bezier(0.4, 0, 0.63, 1) | 离场加速：走的时候越动越快，不拖泥 | 全部 leave |
| `--缓匀` | cubic-bezier(0.4, 0, 0.2, 1) | 对称档：hover/focus/主题等无方向态切换 | 表面态 transition、栅轨塌合、主题色翻转 |
| `--缓往返` | cubic-bezier(0.37, 0, 0.63, 1) | 循环档：in-out，接缝不跳 | `.加载条::after` |
| `--位移近` | 8px | 同层视差：路由页与侧栏的水平位移 | `页-*`/`栏` 的 translateX |
| `--位移中` | 14px | 上浮入场纵向位移 | `@keyframes 上浮入场` |
| `--栏宽` | 248px | 侧栏轨道宽度 | `.外壳.有栏` 栅轨、`.侧栏 > *` 的 min-width |

口径：

- `@keyframes` 内部的几何值（`scale(0.4)`、`stroke-dashoffset: 1`、`translateX(-110%)`、`0%/100%`）保持字面量，强行 token 化只会把可读的图形参数拆散；但节奏值（时长 / 延迟 / 缓动 / 入场位移）即使在 keyframes 里也必须走 token。
- 同一层级、同一性质的表面必须同档。历史上 `160ms ease` / `180ms ease` / `150ms ease` / `300ms ease` 各写各的，观感就是「各动各的」；现在它们分别塌成 `--时长短` 与 `--时长中`，全站只剩一条节奏。
- 新增动画类不需要再来登记 reduced-motion 名单（见第五节）。

## 二、方向感知规则

方向的真源是 `App.vue` 的 `导航` 数组顺序，由 `const 导航序 = 导航.map((项) => 项.路径)` 派生后作为参数传给纯函数 `页面过渡名(导航序, 旧页, 新页)`。`src/动效.ts` 内不得出现任何路径字面量——它只接参数，因此全站导航序只有 `导航` 那一份，不存在第二份顺序表（后端 `RBAC矩阵.test.ts` 继续直读该数组字面结构，形态不得动）。

判定顺序（`qian-jin` = 新页从右侧进场、旧页向左退场；`hou-tui` 镜像）：

1. 无上一页（冷启动首屏）→ 前进（中性）。「无上一页」的唯一真源是 `App.vue` 的 `已提交端点`：只有 `当前路由.matched.length > 0` 的端点才算「来过一页」，vue-router 的 `START_LOCATION` 占位路由（`path: '/'`、`matched: []`）不是页面，与任何首帧目标都没有导航序关系。FP-10 之前这里传的是 watch 的 `旧端点`，占位路由被当成上一页，于是冷启动直连 `/deng-lu` 因 `需登录` 翻转而判成后退（DEF-2）；判据 `需登录` 那条规则本身没错，错在把占位路由喂成了旧页。
2. 两端「是否需登录」不同 → 进需登录页为前进，回免登录页（登录页 / 注销）为后退。登录页与业务页互跳由此覆盖，不需要认识 `/deng-lu` 这个字面量。
3. 两端都需登录 → 比 `导航位次`：新秩大者前进。`导航位次` 取**最长前缀**匹配，所以 `/zhang-hao/42` 认作 `账号管理` 那一档，父目录不被子路由抢位。
4. 同秩（列表 ↔ 详情）→ 比路径深度，更深者前进；同深度互跳（详情 ↔ 详情）算前进。
5. 任一端完全不在登记表内（未知路径）→ 离开登记表为后退、进入登记表为前进；两端都不认识时中性前进。未知路径不参与排序猜测。

`需登录` 取自路由 `meta.xuYaoDengLu`，缺省按「需登录」处理，与 `router/index.ts::守卫判定` 的 `?? true` 同口径。

过渡族名 `页-qian-jin` / `页-hou-tui` 的后缀取拼音，与 `xing-tai="cuo-wu"`、`ming-cheng="zhang-hao"`、`data-testid` 同族：它是跨 TS 与 CSS 两侧流转的内部码位（Vue 会把族名拼成四个 CSS 类后缀），不是显示名，因此按 `docs/命名规约.md` 的码位惯例走 ASCII-safe 拼音；类族前缀（`页-`、`栏`）仍中文。静态挂在模板上的 `name="栏"` 属钩子位，直接写中文。守卫把 TS 常量与 CSS 类名两侧对拼，任一侧改名即判红。

接线时序（改动前必须知道的不变量）：方向在 `watch(当前端点, …)` 的 **pre-flush** 回调里写入 `页面过渡` ref，因此 `<Transition :name>` 在换页那一帧读到的已是新方向。同一个回调里 `已提交端点.value = 新端点` 必须写在算方向**之后**（先算后提交，否则本页成为自己的上一页，方向恒为前进）。`动效守卫` 用一枚 `.guo-du-dang` 标记元素把这条时序做成机器断言：切页后第一个 `nextTick` 上标记文本就必须翻成 `页-hou-tui` / `页-qian-jin`。标记探针是外壳接线的**副本**，副本会漂移——DEF-2 正是这样溜过 293 例的（探针一律 `await 路由器.push()` 后再挂载，永远看不到首帧），因此探针与外壳两侧都有锁：探针自己按 `已提交端点` 同构重写并补了「挂载先于初始导航完成」的冷启动用例，另有 `外壳的方向接线以「已提交端点」为唯一上一页真源` 与 `FP-10 DEF-2 外壳真实接线` 两条分别锁源码形状与外壳实际读数（后者经 `包装.vm.页面过渡` 直读 `<script setup>` 绑定，jsdom 下 `<Transition>` 的类名要等 rAF 才落地，读 ref 才是确定性的）。

## 三、合成层约束

只有 `transform` 与 `opacity` 可以参与**长动画与进出场**：页面 `页-*` 四态、侧栏 `栏` 四态、`上浮入场` / `点现` / `微光扫`。守卫有两道扫描：`transition:` / `animation:` 的属性位命中布局触发属性即判红；`@keyframes` 帧体采用**白名单**（只放行 `transform` 与 `opacity`），其余属性必须显式登记豁免，否则判红。

禁止作为过渡 / 动画属性的清单（会触发布局或整页重绘）：`width`、`height`、`min-*`、`max-*`、`top`、`left`、`right`、`bottom`、`inset`、`margin*`、`padding*`、`display`、`position`、`font-size`、`line-height`、`letter-spacing`、`grid-template-columns`、`grid-template-rows`、`flex-basis`、`vertical-align`。

Paint-only 允许但不鼓励扩散的清单：`background-color`、`color`、`border-color`、`box-shadow`、`fill`、`stroke`——只用于 `--时长微`~`--时长短` 的表面态，不得用于进出场。

现存四条豁免（守卫侧白名单，逐条带理由，失配即判红；养僵尸也判红）：

| 豁免 | 理由 |
| --- | --- |
| `input.输入:-webkit-autofill` 的 `transition: background-color 5000s ease-in-out` | 5000s 不是节奏值而是「背景色永不淡出」的 Chrome 兜底技巧；该声明同时被 `视图守卫` 的 autofill 断言锁死，改坏即两头红 |
| `.条充` 的 `transition: width` | 进度条填充的语义就是宽度；换 `transform: scaleX` 要改 DOM 与 `transform-origin`，属 FP-05 组件动效面 |
| `.外壳` 的 `transition: grid-template-columns` | 见第四节，时长已锁死为最短档 `--时长微`，且必须与 `栏` 族进出场同档并行 |
| `@keyframes 描线现` 的 `stroke-dashoffset` | SVG 描线的既有语义，dashoffset 不参与 HTML 布局 |

四条豁免都必须被守卫的「白名单消费计数」真命中一次：任何一条不再有使用者即判红（防僵尸豁免）；反过来 autofill 那条失配也会判红，等于同时给 `:-webkit-autofill` 兜底上了一道保险。

## 四、侧栏进出与栅轨代价

`<aside v-if>` 外面包一层 `<Transition name="栏">`，同时把 `.外壳` 在 ≥960px 恒定设为 grid：未登录 `grid-template-columns: 0px minmax(0,1fr)`，登录加 `.有栏` 变 `var(--栏宽) minmax(0,1fr)`，`--栏宽` 从 0 走到 248px。

- **为什么必须动 `grid-template-columns`**：正文区的可用宽度是这条轨道决定的。用 `transform: translateX` 推侧栏只会让侧栏滑走而正文宽度纹丝不动（观感是「侧栏飞出、内容不回弹」），或者要求正文也一起 translate，那会在滚动容器里留下空白。塌轨道是唯一能让「侧栏退场 + 正文补位」同步的做法。
- **代价**：轨道宽度变化会触发布局与重绘。已用三招压到最低——时长锁 `--时长微`（120ms，全站最短档）、`.侧栏 { overflow: hidden }` 把内容裁在轨道内、`.侧栏 > * { min-width: var(--栏宽) }` 让栏内内容始终以 248px 布局，于是观感是「从右边缘擦除」而不是文字反复折行（后者才是可读的布局抖动）。轨道不再扩宽时 `overflow: hidden` 与 `min-width` 都是无视觉开销的恒等式。
- 侧栏 leave 只做 opacity、不做 transform：离场期间轨道已塌到 0，再平移会把内容推到正文上方。

## 五、reduced-motion 策略

`@media (prefers-reduced-motion: reduce)` 内只有一条通配规则：`*, *::before, *::after { transition: none !important; animation: none !important; }`，外加撤掉 `.加载条::after` 的微光层。

旧实现把 `animation: none !important` 手工枚举成 8 个选择器，任何新增动画类不追加进去就会在「减少动效」偏好下继续动——这是无障碍真缺陷的根因。通配化后新类自动被覆盖，因此守卫反向锁死：reduce 块里再长出第二条设 `animation`/`transition` 的选择器即判红（不得回退成枚举）。

`transition-duration` 走通配后，主题色翻转与栅轨塌合在该偏好下同样瞬时完成，无需额外分支。

**通配的另一面（FP-08 补）**：`animation: none !important` 抹掉的不只是运动，还有 `fill-mode` 的填充值。因此本项目的硬不变量是——**任何节点的可见终态都不得外包给 animation 填充**：基态自身必须就是可见的，animation 只负责"从别处走来"。违反者的表现是 reduce 偏好下节点永久隐形（不是"没有动画"，而是"看不见"）。守卫 `扫描填充依赖` 按这条机械核销：全站（含组件 `<style>` 块）凡 `animation`/`animation-fill-mode` 带 `both` 或 `forwards` 的规则，同规则体内不得出现 `stroke-dashoffset` 非零、`opacity` 非 1、`visibility` 非 visible、`scale(0)` 一类的隐藏基态；`backwards` 与 `infinite` 不在此列（它们只影响入场前的一帧，终态本就归基态）。

`backwards` 与 `both` 的区别正是这条判据的落点：`上浮入场`（`backwards`）与 `点现`（`backwards`）的基态自身可见，reduce 下退化为"直接到位"，安全；`微光扫` 的基态无副作用且 reduce 块另有 `.加载条::after { display: none }` 撤掉微光层，安全；`描线现` 曾用 `both` 且把 `stroke-dashoffset: 1` 写进基态，于是 reduce 下折线永久停在"未描"的那一端。

**归因（照实记录，不抢功也不背锅）**：`.描线` 的这条缺陷是**基线 0f3f8c5 既有**——基线的 reduce 块用手工枚举名单，名单里第一项组就是 `.正文 > section … .描线, .图点`，`.描线` 当时同样被 `animation: none !important` 命中且同样写着 `stroke-dashoffset: 1` 基态。FP-04 把它通配化只是让这个既有缺陷从"枚举命中"变成"通配命中"，既不是引入者也没有让它变好；FP-08 才是修掉它的那一轮。修法取"删基态的 `stroke-dashoffset: 1`"而非"在 reduce 块补一条归零"：`both` 的 backwards 填充本就覆盖 `--时长短` 的延迟期，非 reduce 路径逐帧不变，而补分支会先把第五节"reduce 块不得再长出第二条枚举"的锁撞开。

## 六、主题切换过渡

`主题模式.ts::应用主题` 仍然只翻 `<html class="dark">`，新增的是：真实翻转（已应用过且值变了）时给 `<html>` 挂 `主题过渡` 类，一个 token 时长后摘掉。挂类期间 `html.主题过渡 *`（含 `::before/::after`）以 `!important` 统一给 background-color / color / border-color / fill / stroke / box-shadow 上 `--时长短` 过渡。

- 首帧装载不挂该类（`已应用主题 === null`），因此刷新页面恢复深色不会闪一下。
- 用 `!important` 是因为它必须在 160ms 窗口内压过各元素自己的 `transition` 简写；不压就会有一半表面瞬时翻色、另一半渐变，正是要修的病。
- 时长不写死在 JS：`令牌毫秒()` 从 `getComputedStyle(documentElement).getPropertyValue('--时长短')` 读，CSS 是唯一定义处；读不到（jsdom、CSS 未装载）返回 0，退化为「无过渡」而不是「另猜一个数」。
- 与 Chrome autofill 兜底共存：`:-webkit-autofill` 那条 5000s 声明不在 `html.主题过渡` 规则的选择器组里被改写，`!important` 只在该类挂着的 160ms 内生效，autofill 的长过渡技巧不受影响；两侧都有守卫断言。
- 类名单源：TS 侧 `const 主题过渡类` 与 CSS 侧 `html.主题过渡` 由 `动效守卫` 对拼，任一侧改名即判红。
- 已知有界代价：`!important` 会在挂类的 160ms 内覆盖同元素上的其它 `transition` 简写，因此「切页或侧栏轨道动画途中点主题按钮」会让那一程退化为瞬时换页/瞬时塌轨（颜色照常渐变）。窗口只有一档最短表面时长（`--时长短`），且不改交互语义，判定为可接受，不为它开第二条实现。

## 七、只开一条渲染路径

本项目**不**引入 View Transitions API、WAAPI 编排库或任何动画依赖，路由/浮层动效只有一条路径：Vue 内置 `<Transition>` + `主题.css` 的 token 化 CSS 类。

理由：

1. View Transitions 与 `<Transition>` 同时上，同一页会有两套生命周期、两套时序真源，浏览器支持矩阵还不同——那不是「更丝滑」，是把根因（缺单一真源）换个形式再犯一遍。
2. `<Transition>` 已是本项目依赖（vue 3.5）的一部分，代价只是 Vue 的 transition 运行时代码被拉进首屏。FP-04 实测：仅两处 `<Transition>` 使用即令首屏 gzip +2366B、全站 gzip +2354B（运行时进了 index 分块），本功能点其余改动（token 层与接线）另加首屏 +433B / 全站 +799B。这是买「一条路径、零新依赖」的价格，不是浪费。
3. 纯 CSS 无法表达「离开的那个页面」——元素一被 `v-if` 撤掉就没有离场帧。`<Transition>` 是 Vue 里唯一能拿到离场生命周期的正规入口。
4. `mode: 'out-in'` 而非叠层：正文是普通文档流，两页同时在场要靠绝对定位堆叠才能对齐，代价是高度塌陷、滚动位置错乱与「双份内容并存」——正是验收禁止的两条。out-in 让离场与进场串起来（120ms + 240ms ≈ 原 `.正文 > section` 的 360ms 入场节奏），任何时刻 DOM 里只有一页；`动效守卫` 的探针用例把「每个观测点 section 数量恒为 1」钉住。
5. `appear` 让冷启动首屏走同一个入场语义，不需要再留一条 CSS 动画兜底。

## 八、双重入场的消解

历史上 `.正文 > section { animation: 上浮入场 360ms ease-out both }` 是页面级唯一入场，但它没有离场对偶。接了路由 `<Transition>` 后，页面根 `<section>` 会同时吃到「keyframes 上浮」+「transition 平移淡入」，观感是抖两下。处理：**删除** `.正文 > section` 的这条 animation，页面级入场语义唯一归 `<Transition>`。

保留的是**页内错峰**：`.账簿表 tbody tr` / `.条组 .条行` / `.统计卡组 .统计卡` / `.气泡列 .气泡` / `.时间线 li` 的 `上浮入场 + --位 * --步进差`。它们动的是行与卡片，和页面级平移不同层级，读起来是「页面到位 → 内容依次落位」的两段编排，不是重复。`--时长长`（360ms）这一档因此失去唯一使用者，已按「无孤立 token」守卫删除。

## 九、交给 FP-05 的组件动效面

消息条出入场、页签切换、思考记录展开/收起、表格行载入、分页切换、按钮按压与禁用态——一律复用第一节的 token 与第五节的通配降级，不得新增裸时长/缓动字面量，不得给 `.条充` 之类布局属性动效再开豁免。侧栏与浮层若需要遮罩，进出场同样走 `<Transition>` + 一族 CSS 类。

- **P4 权限位**：`登录仓库.可高危` / `可封禁` / `可封禁审核` 门控的 17 处（`审核运营` 7、`账号列表` 6、`封禁管理` 4）。不接过渡的依据是时序事实而非观感：能力位由 `stores/登录.ts` 的 `const 能力列表 = ref(读能力())` 同步初始化，而**跨浏览器重开的自动登录路径**（FP-03 新造：只有 localStorage 持久标记 + 勾选自动登录）在冷启动那一刻能力位必然是空的，页面若先挂载就会在身份接口回包后把高危/封禁入口**瞬时补出**。修法是在路由放行前把这段等待消化掉：`router/index.ts::注册守卫` 的 `beforeEach` 改为 async，命中 `持久令牌冷启动()`（`读会话令牌() === null && 读持久原始(会话键) !== null`）**且该目标无会话就进不去**（`守卫判定(目标.path, null, false) !== null`，复用同一份需登录判定而不是再抄一份路径字面量，登录页因此照旧秒开、也不会为它白白烧掉一次轮换）时，先 `await 使用登录仓库().冷启动会话()` 再重新跑一次 `守卫判定`；`冷启动会话()` 是单次闸门（`冷启动已续期` 置位后直接返回 `已登录`），因此 `App.vue` 的 `onMounted` 与守卫共用同一次轮换，不会重复打 `/shua-xin`，也不会让已登录用户每次跳页都再等一次。等待失败一律不卡死：401 走 `归一请求错误` 的既有路径（清令牌 + 回登录页，仍可手动登录），429/网络抖动只返回 false 并放行，权限入口按空能力渲染（服务端仍是唯一授权边界）。守卫的 `权限位前提()` 用三条机器断言钉住这个前提：能力位同步初始化、`能力列表.value =` 的写点全部封闭在 `设置身份`/`同步存储`/`退出登录` 三个函数体内、守卫源码确实存在"持久冷启动 → await 冷启动会话 → 重新判定"的放行路径。
  - **FP-10 收口（DEF-1）**：守卫等的是**页面**，等不到**外壳**——`App.vue` 的 `<aside>` 在初始导航落地前就已经渲染完首帧，而跨浏览器重开时持久会话标记在 `localStorage`、身份缓存只在 `sessionStorage`，`会话标识` 有值而 `能力列表` 为空是这条路径的必然首帧，于是侧栏从「0 项 + 角色区加载中」在一个身份往返后跳到 7 项（真浏览器实测 31ms，冷启动路径 `shua-xin` 112→143ms；本机暖链路短到 jsdom 的 293 例又一律 `await flushPromises()` 后才数条目，所以量不出来）。修法取"区分确实无权限与尚未解析"而不是给侧栏补动画：`App.vue` 的 `身份待解析 = 已登录 && 管理角色 === null && !身份已复核` 为真时，`栏导航` 里渲染 `导航.length` 条 `.栏占位`（与真条目同框：`.栏导航 a` 的盒模型选择器组共享 `padding`/`border-left`/`font-size`，行盒由 `.栏占位::before { content: '\00a0' }` 撑出，因此逐行等高且零数值复刻），身份落地即整批摘掉。角色区不改判据：`管理角色 === null → 通用文案.加载中` 本来就是"尚未解析"的如实表达且单行等高，无跳变可修。**不取**"把角色/能力也镜像进 `localStorage`"那条更省字节的路：它会让首帧显示上次会话的权限面，与 `架构文档.md` 七「身份以服务端查库结果为准」的口径相反，且要改 `设置身份`/`清除令牌` 的持久档语义（`会话生命周期.test.ts` 的「不勾记住密码登录：localStorage 不留任何东西」正是它的反证）。占位不得常驻由 `身份已复核`（在 `同步身份` 的 `finally` 里置位）兜住：429/网络抖动复核失败时按空能力如实渲染 0 项，与 P4 既有的"放行不卡死"口径一致，这条有独立用例锁死。
- **P5 分支**：`ShuJuBiaoGe` / `账号详情` 的单元格互斥渲染（徽标 / 链接 / 插槽 / 文本）与 `TuBiao` 的 12 路图标选形。它们由列定义与 `项.插槽` 静态选定，同一次渲染里只取一臂，不是"出现又消失"的面。判据要求表达式**不得含 `?` / `||` / `&&` / `.length`**——`mingCheng === 'x'` 这类常量比较才是静态选形，掺了运算符就是运行期可翻转的动态选形，必须自己接族。链上各臂（`v-else-if` / `v-else`）继承链首判据，继承前同样先过运算符关。
- **P6 随行**：`思考链.vue` 时间线里 3 个 `当前标签 === 'si-kao-ji-lu'` 门控的行内节点。切页签时 `切换标签()` 先把 `行列表` 清空，父级 `块` 族整块离场再重新进场，行内节点不会单独被看见。守卫要求这类节点必须有祖先族，且该视图的切换函数确实清空 `行列表`。
- **P7 装载属性**：`YeMei.vue` 的 `页眉说明`。除"是 `defineProps` 的静态属性且组件内无同名 ref"外，判据还要求 grep 全站所有 `:shuo-ming="…"` 调用点，实参必须逐个命中 `^\w+文案\.\w+$` 或字符串字面量——只在组件侧证明"它是 prop"不构成恒定性，调用点改传响应式值就会让它中途翻转。
- **P8 弹层与浮层（FP-05b）**：`components/QueRenCeng.vue` 的确认层。过渡做在组件根（`<Transition name="层">` 包 `v-if="xianShi"` 的遮罩层），调用点（`账号列表.vue` 的高危二次确认）无条件挂载组件、不写 `v-if`，因此台账只增根节点这 1 站。它与 P1 同构：出入场做进共享组件根，全站开窗一条路径。不用原生 `<dialog>` 的理由：`showModal()` 是命令式生命周期，与 `v-if` 声明式过渡天然两条路径（违反第七节单路径约束），且 jsdom 对 `showModal` 支持面未验证；遮罩用普通 div，可访问性靠 `role="dialog"` + `aria-modal` + 自实现焦点圈定补足。
- **已废除的 P7「恒定:内建过渡」**（FP-08）：原判据只看"该标签的组件根有没有族过渡"，把 `思考链.vue` 的 `<XiaoXiTiao v-if="!说明 || …">` 判成已覆盖。但 `v-if` 写在**调用点**是整组件挂载/卸载，`XiaoXiTiao` 根上的 `<Transition name="条">` 没有 `appear`，两向都不进 Vue 的 enter/leave 钩子＝瞬时出现消失——"组件内部有动画"从来不等价于"组件挂载/卸载有动画"。该站点改为 `:xian-shi="!说明 || 说明.dai_bu_chong.length === 0"`，与同视图另外 3 个 `XiaoXiTiao` 调用点同构，出入场由组件根的 `条` 族真正承担；判据本身从表里删除，守卫同时新增两条锁：条件节点的标签一律不得是内建过渡组件（`XiaoXiTiao`/`ShuJuBiaoGe`/`QueRenCeng`），以及一条 jsdom 行为断言证明 `条` 族的 enter 与 leave 类在两个方向都被真消费。

浮层与开窗的实测结论（FP-05 自查、FP-05b 收口）：`Grep -n "dialog|modal|浮层|遮罩|popover|drawer|抽屉|position: fixed" 管理前端/src` 命中 `主题.css` 的 `body::after`（全站噪点层，`pointer-events: none`，非交互面）与 FP-05b 新增的 `.确认遮罩`。历史上唯一的"开窗"是 `views/账号列表.vue` 高危操作前的 `globalThis.confirm(账号文案.高危二次确认)`——它由操作系统绘制，没有 DOM 节点，CSS 与 `<Transition>` 都碰不到。FP-05b 已把它换成站内 `QueRenCeng` 确认层（`层` 族进出场 + 焦点圈定 + Esc 取消），`src` 非测试代码内 `confirm(` 出现次数由 `确认层.test.ts` 归零锁死；服务端 `que_ren: true` 与 `XU_YAO_QUE_REN` 门禁原样保留，前端确认层不是安全边界。

## 十一、四族选型、桩规避与已知代价

- 档位分配：`条` 与 `组` 用 `--时长短` 进（160ms）+ `--位移近` 纵向、`--时长微` 出（120ms）；`块` 只淡入不平移，进场 `--时长中`（240ms）、离场 `--时长微`，因为它承载的表格/卡片/时间线已有行级错峰入场，再加一层纵向位移就是双重运动；`层`（FP-05b 确认层）是盖在全页之上的开窗，进场 `--时长中` + `--位移近` 上浮（物体从眼前举起），离场 `--时长微` 淡出下沉，与路由离场同档保证"开窗重、关窗快"。四族一律只用 `transform` 与 `opacity`，不碰布局属性，未新增任何豁免条目。
- 离场塌高：`v-if` 撤节点必然让后续内容上移，而 `height`/`max-height` 属第三节禁动的布局属性且不得再开豁免，所以离场结束那一帧存在一次高度塌合，被 120ms 的最短档淡出压到最小说明。这是选型的既知代价，不做第二条实现。
- reduced-motion：新族完全依赖第五节的 `*, *::before, *::after` 通配，没有进 reduce 块，也没有任何 `!important` 动效声明。守卫反向锁死：族类名出现在 reduce 块内、或任何带 `-enter-` / `-leave-` 的选择器使用 `!important`，即判红；全表允许出现 `!important` 的动效规则仍然只有 reduce 通配与 `html.主题过渡` 两条。
- 测试桩规避（改了就会坏，必须记）：`@vue/test-utils` 默认把 `<Transition>` 换成 `<transition-stub>` 元素桩，任何把过渡做在组件根上的写法都会让 `mount(组件).classes()` / `attributes()` 读到桩而落空。`src/__tests__/setup.ts` 因此显式声明 `config.global.stubs = { transition: false, 'transition-group': false }`，让 jsdom 跑真实的 Vue 过渡运行时——`transition-stub` 桩从来不是任何断言的对象，关掉它只增测试保真度（FP-04 的 out-in 探针用例从此真的在验 `<Transition>`），不减任何断言。jsdom 不注入 CSS，过渡时长为 0，进出场同步 resolve，故 `视图守卫` 的聚合文本断言无需 `flushPromises`。
- 体积：本轮新增 6 条 CSS 规则与 29 处 `<Transition>` 站点，`<Transition>` 运行时已在包内（FP-04），因此只增 CSS 与模板编译产物，JS 侧不再引入依赖。
- **离场期间不可交互（FP-08）**：`mode: 'out-in'` 的语义是"旧页先在 DOM 里停 120ms 再换"，这 120ms 里旧页的按钮仍挂着 handler，管理员点在离场动画上就会触发上一张页面的动作。修法是一条后缀通配规则 `[class*="-leave-active"] { pointer-events: none }`，不枚举族名因此新族长出来也自动生效（`动效守卫` 断言这条规则全站恰好一条、规则体恰好那一条声明，并把 `-leave-active` 后缀本身当作契约核对：`条`/`组`/`块`/`层`/`栏`/`页-qian-jin`/`页-hou-tui` 七个族都得真有 leave-active，否则通配落空）。**残留**：`pointer-events` 只挡指针不挡键盘，离场帧里被聚焦的元素仍可能被 Enter 触发；且节点被摘除时若焦点正落在其上，焦点会退回 `<body>`。彻底闭环要 `inert`（要 JS）或焦点归还器，代价与本条量级不匹配，转 FP-06 键盘取证坐实后再判。
- **播报维度（FP-08 正式记账）**：`XiaoXiTiao` 的 `role`（`cuo-wu` 时 `alert`，否则 `status`）与 `aria-live="polite"` 挂在被 `v-if` 整体插拔的 `<p>` 上——这是基线既有形态，但本项目从 FP-05 起正式把 insert/remove 当成动效语义，就必须承认 ARIA 的可靠播报要求 live region **先在场、再变内容**。`role="alert"` 的动态插入各家读屏一般仍播报，`status`/`polite` 的整节点插入则明显更不可靠。本轮不改形态（改成长驻 region + 文本替换会同时打掉 `条` 族的出入场与 `视图守卫` 的根节点断言），列为已知限制并转 FP-06 读屏取证。
- **`QueRenCeng` 的 aria 锚点已实例唯一（FP-10 DEF-7）**：原先 `aria-labelledby="que-ren-ceng-biao-ti"` / `describedby` 是硬编码静态 id，同页挂第二个实例就会互相指错节点。当时的处置是"加守卫不加唯一 id"，把单实例当作隐含前提锁死；FP-10 按预授权的顺序（"届时要先改实例唯一 id 再登记"）改掉静态字面量：组件内一个模块级 `层实例计数`（`<script lang="ts">` 普通块，`<script setup>` 里的顶层声明是每实例重跑的，做不了实例计数）给每个实例发一个序号，标题/正文锚点为 `que-ren-ceng-biao-ti-<序号>` / `que-ren-ceng-zheng-wen-<序号>`，一律 `:id` + `:aria-labelledby`/`:aria-describedby` 绑定。守卫两侧同步升级：`动效守卫` 源码侧从"静态 id 恰好两个"改为"恰好两个 `:id` 绑定、零静态 `id="…"`、且 aria 引用的表达式与 `:id` 用的是同一对锚"，`确认层.test.ts` 另加一条行为断言——同时挂两个实例，逐个 `getAttribute` 反查 `getElementById`，证明两对锚互不相等且各自指向自己的标题与正文。`<transition-stub>` 与 `aria-*` 反查文本的既有断言全部保留（锚点值不再是常量，所以那两条必须按属性值反查而不是按字面量匹配，实测它们未改一字仍绿）。挂载点仍只登记 `账号列表.vue` 一处：唯一 id 解除的是 id 冲突，台账 P8 的站点数仍要新增时再改，两处不能同时不动。
