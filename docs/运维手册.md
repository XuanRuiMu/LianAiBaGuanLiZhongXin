# 运维手册（恋爱吧数据中心 P0）

## 1. 日志规范

统一格式：`时间 级别 [模块] 追踪号=<id> 消息`。

- Python 服务（ai-service、tts-service）：标准输出，附 `X-Trace-Id` 响应头（请求可自带该头串联全链路）。
- 后端（backend-java）：控制台 + `logs/app.log`，`infra/logback` 按 10MB/30 天切割（容器内 `/app/logs`，已挂载 `backend_logs` 卷）。
- 查看：`cd infra && docker compose logs -f backend-java ai-service tts-service`。
- 日志不记录密码、令牌、用户原文之外的敏感信息。

## 2. 备份恢复

脚本：`infra/scripts/backup.sh|backup.ps1`（备份）、`restore.sh|restore.ps1`（恢复）。

- Linux：`cd infra && ./scripts/backup.sh`，备份落 `./backups/<时间>/`（`mysql.sql` + `source-postgres.sql`）。
- 自定义目录：`BACKUP_DIR=/data/bak ./scripts/backup.sh`。
- 恢复：`./scripts/restore.sh ./backups/<时间>`。
- 演练：`DRY_RUN=1 ./scripts/backup.sh` / `DRY_RUN=1 ./scripts/restore.sh <目录>`；Windows 用 `-演练` 开关。
- 演练记录见《备份恢复演练记录.md》。

## 3. 死信可观测与重放

- 状态总览：`GET /api/v1/sync/status`（需登录），含最近 10 条同步日志与各类型最后成功时间。
- 死信查询：`GET /api/v1/sync/dlt?limit=20` 或 `GET /api/v1/sync/dlt?batchId=Bxxxx`（需登录）。
- 死信重放：`POST /api/v1/sync/replay?batchId=Bxxxx&types=USERS,MESSAGES`（需登录；不传 `types` 则重放该批次全部失败类型；同批次号幂等，已成功类型自动跳过）。
- 批次号仅允许字母数字与连字符（≤64 字符），非法直接 400。

## 4. MCP

- AI 服务将工具总线以 Streamable HTTP 挂载于 `http://<AI服务>/mcp`（可用 MCP 客户端列出 `query_overview`、`query_user_trend`、`query_favorability`、`query_retention`、`search_knowledge` 并调用）。
- 开关：环境变量 `MCP_ENABLED=false` 可关闭挂载。

## 5. 限流

- `/api/chat/stream`：默认每身份 60 秒 30 次（`CHAT_RATE_LIMIT` / `CHAT_RATE_WINDOW_SECONDS`），超限 429。
- `/api/tts/synthesize`：默认每身份 60 秒 60 次（`TTS_RATE_LIMIT` / `TTS_RATE_WINDOW_SECONDS`），超限 429。

## 6. 常见故障

| 现象 | 排查 |
| ---- | ---- |
| `/api/chat/stream` 返回 401 | 前端是否携带登录令牌；`JWT_SECRET` 三服务是否一致 |
| 同步一直失败并进死信 | 查 `/api/v1/sync/dlt` 错误信息；确认源库连通与只读账号权限 |
| Kafka 健康检查失败 | 等待 40 秒以上再查；确认宿主 9092 未被占用 |
| 前端空白 | 确认构建参数 `VITE_API_BASE`/`VITE_AI_BASE` 指向可访问地址 |
| 磁盘告警 | 清理 `backend_logs` 卷旧日志与 `./backups` 过期备份 |
