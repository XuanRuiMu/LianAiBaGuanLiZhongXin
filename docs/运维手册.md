# 运维手册（恋爱吧管理中心 P0）

## 1. 日志规范

统一格式：`时间 级别 [模块] 请求号=<X-Request-Id> 消息`；管理后端全链路透传 `X-Request-Id/X-Trace-Id`，前端请求层（`管理前端/src/api/请求.ts`，原生 fetch）逐请求自动携带两个同值头，健康分级见 `/api/jian-kang`（存活）`/api/ready`（就绪）`/api/zhi-biao`（指标）。

- Python 服务（tts-service）：标准输出，附 `X-Trace-Id` 响应头（请求可自带该头串联全链路）。
- 查看：`cd infra && docker compose logs -f management-backend tts-service n8n`。
- 日志不记录密码、令牌原文；手机号脱敏，敏感键丢弃。

## 2. 备份恢复

脚本：`infra/scripts/backup.sh|backup.ps1`（备份共享库只读转储）、`restore.sh|restore.ps1`（拒绝恢复）。

- Linux：`cd infra && ./scripts/backup.sh`，备份落 `./backups/<时间>/`（`lovewithme-pg.sql`，共享库只读转储）。
- 自定义目录：`BACKUP_DIR=/data/bak ./scripts/backup.sh`。
- 恢复：管理中心只读，恢复脚本一律拒绝；恢复请在和我恋爱吧侧执行。
- 演练：`DRY_RUN=1 ./scripts/backup.sh` / `DRY_RUN=1 ./scripts/restore.sh <目录>`；Windows 用 `-演练` 开关。
- 演练记录见《备份恢复演练记录.md》（双栈时期记录，已冻结备查，见 docs/archive/）。
- 恢复目标：RTO 60分钟/RPO 15分钟（BEI_FEN_BAO_LIU_TIAN默认30天/HUI_FU_YAN_LIAN_JIAN_GE_TIAN默认90天可配）；管理侧只验备份可读性加校验和，恢复演练到和我恋爱吧侧执行。

## 5. 限流

- `/api/tts/synthesize`：默认每身份 60 秒 60 次（`TTS_RATE_LIMIT` / `TTS_RATE_WINDOW_SECONDS`），超限 429。
- 管理后端：读接口默认每用户 60 秒 100 次，写接口（登录/封禁/授予角色/接管角色等）默认每用户 60 秒 10 次，超限 429 `XIAN_LIU`。

## 6. 常见故障

| 现象 | 排查 |
| ---- | ---- |
| `/api/tts/synthesize` 返回 401 | 确认携带管理令牌或正确 `X-Internal-Token`；两边 `JWT_SECRET` 是否同源 |
| 管理登录 400 账密错 | 确认手机号为管理员行且密码正确；新置密码后需用新密码登录 |
| 管理接口 403 | 令牌验签通过但用户表旗标非管理员，换管理员账号 |
| 共享库连不上 | 确认和我恋爱吧侧 postgres/redis 容器健康；`DATABASE_URL`/`REDIS_URL` 是否从主配置源补齐 |
| 编排服务不健康 | 等待 60 秒以上再查；确认宿主 5678 未被占用 |
| 磁盘告警 | 清理 `./backups` 过期备份 |

## 8. 专用测试超管账号（seed）

- 用途：给管理端 RBAC 与会话端到端实测提供一个口令已知的超管账号。`管理员`/`运营`/`审核员` 三旗标全开，`取管理角色` 按 管理员 > 运营 > 审核员 优先级解析为 `chao_guan`，登录回传 `角色能力矩阵` 的全量五位。
- 脚本：`管理后端/scripts/建测试超管账号.ts`，只用管理后端既有运行时与依赖（Node + `pg`/`bcryptjs`/`dotenv`/`ts-node`），零新依赖，不进 `dist`、不进前端包。
- 执行：`cd 管理后端 && npx ts-node scripts/建测试超管账号.ts`。连接串取 `管理后端/.env` 的 `DATABASE_URL`，留空时按《架构文档》「环境同源」从 `和我恋爱吧/.env` 补齐；脚本任何情况下都不回显连接串。
- 口令：默认 `crypto.randomBytes(18)` 的 base64url，拒绝采样直到满足管理端登录复杂度（8–200 位且同时含字母与数字，口径源 `管理后端/src/路由/登录.ts`），以 `bcryptjs` cost 12 入库（与 `src/启动.ts` 时序均衡所用代价同源）。**只在 stdout 打印一次**，不落盘、不入日志、不进任何入 git 的文件。要自带口令走环境变量 `CE_SHI_CHAO_GUAN_KOU_LING`，不走命令行参数（命令行参数会进进程表）。
- 幂等语义：`INSERT ... ON CONFLICT ("手机号") DO NOTHING RETURNING "ID"`，依赖实测存在的 `用户_手机号_key` 唯一索引；同手机号再跑输出「已存在」，总行数不变。脚本只插入，任何分支都不含 UPDATE/DELETE，由 `管理后端/tests/单元/建测试超管账号.test.ts` 锁定。
- 账号常量：手机号 `13900000002`、用户名 `测试超级管理员`（`用户名` 同为唯一列）。撞号时改这两个常量并同步本节，禁止改既有行。
- 口令是单向哈希，找不回：忘记口令 = 删号重建。
- 删除回滚 SQL：

  ```sql
  -- 先确认目标行（应为 管理员/运营/审核员 全真、测试 为假）
  SELECT "ID", "手机号", "用户名", "管理员", "运营", "审核员", "测试"
    FROM "用户" WHERE "手机号" = '13900000002';
  -- 回滚：只删这一个测试账号
  DELETE FROM "用户" WHERE "手机号" = '13900000002';
  ```

- 共库事实：该行落在与和我恋爱吧同库同表的 `"用户"` 上，游戏侧正常「手机号 + 口令」登录同样能用它（口令按各自口径校验）。故意**不置** `"测试" = true`：游戏侧 `POST /测试用户登录` 对 `"测试" = true` 的行免口令签票，给带管理旗标的行打该旗标等于新开一条提权通道。
- 与游戏侧建号接口不重叠：`和我恋爱吧/backend/src/services/管理员.ts::chuangJianCeShiYongHu`（`/测试用户`，超管高危门禁）建的是 `管理员=false, 测试=true` 的玩家测试号，产不出管理旗标；管理端取证一律用本脚本。
- 边界与注意：
  - 仅限本地/测试共享库。该库未来一块部署到服务器，因此**上线前必须按上面的回滚语句删号**，否则会留一个手机号公开、口令无人记得的超管入口。
  - 脚本直连库写行，不经管理后端路由，`审计日志` 里不会有这条建号记录（与 `/测试用户` 那条链不同）；口令也不进任何日志。
  - 不要把本脚本的 stdout 重定向进任何入库文件、CI 日志或聊天记录；要交接口令就临时存到仓库外的本地临时文件，用完即删。
  - `CE_SHI_CHAO_GUAN_KOU_LING` 只作进程内注入，禁止写进 `.env` 或任何配置文件。
  - 三旗标全开只保证拿到超管（`chao_guan`）与全量能力位：`取管理角色` 按 管理员 > 运营 > 审核员 短路，所以该账号**不能**用来验证 运营/审核员 的角色解析与降权路径，那需要单独的行。
